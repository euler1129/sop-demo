# 踩坑清单（都已在真实文件上踩过）

## 一、Visio `.vsdx`

### 1. 页面文件映射不能猜
`Page ID` 与 `visio/pages/pageN.xml` 的文件名**经常不一致**（真实文件里 ID 是 0/5/8，文件名是 page1/2/3）。
必须读 `visio/pages/_rels/pages.xml.rels` 建 `rId → Target` 映射，
再从每个 `<Page>` 的**子元素** `<Rel r:id="rIdN"/>` 取 rId。
- 从 `Page` 的属性取 rId → 取不到，只会解析出 1 页。
- 用 `Page ID` 拼文件名 → 直接报错或解析出 0 页。

### 2. Group 常常没有 Height 单元格
Visio 的 Group 形状只写 `PinX/PinY/Width`，**不写 `Height`**。
`h = 0` 会让所有泳道、环节列被判成"不是节点"，整批丢失。
必须分三阶段：建树（保留局部坐标）→ 自底向上按子形状补算 Height → 自顶向下折算绝对坐标。

### 3. 连线端点落在子形状上
`Connect` 表里的 `ToSheet` 常指向 Group 内部的小形状（例如"分开的事件"的上下两半）。
必须从该形状沿父链条向上回溯到"最近的节点祖先"，否则 `edges` 全空。

### 4. 节点与容器靠容器的 Master 名 + 几何形状判别
- 竖列（业务环节）：`Swimlane (vertical)`，高且窄，`h >= maxH*0.5 && h/w >= 1.8`
- 横条（角色泳道）：`Phase List` / `Separator (vertical)`，宽且扁，`w >= maxW*0.5 && w/h >= 1.8`
- 结构容器：名字含 `Container` / `List` / `Background` / `Legend` / 以 `Title` 开头 →
  自身与**全部后代**都不参与节点识别（否则标题、页脚、图例会被当成流程节点）
- `Separator` **不能**当容器：它常常就是真正的角色泳道，屏蔽掉会把整条泳道弄没
- 更可靠的一路是 Visio 自带的 **`Function` 自定义属性**（业务环节列标题），
  它能直接给出节点归属哪个环节；属性缺失时才回退到几何推断

### 5. "分开的事件"（Divided event）的两个子形状
一个写动作、一个写承载系统，但**哪个在上哪个在下因作者而异**。
判别策略：短且含「系统 / 平台 / 邮件 / EDI / API / APP / 小程序…」字样的那个当系统，另一个当节点名；
都判断不出来时，取第一个当名称、其余全部进 `note`，不要丢信息。

## 二、Excel `.xlsx`

1. **合并单元格读出为空**：靠"序号 / 业务环节 / 操作节点"三列**向下填充**（沿用上一个非空值）来恢复层级。
2. **单元格内混排结构化内容**：同一个"业务操作说明"格里写着 `情况1：…` `情况2：…` `正常…` `异常…` `/ 产生费用：…`，
   且用**缩进续行**表示同一分支的后续内容。必须按行首关键字切分成分支 / 异常 / 费用，
   整段塞进说明字段等于把 90% 的信息量丢掉。
3. **尾部空行**：抽取时先去掉全空尾行，否则前端会多出空节点。
4. 行宽不一致要补齐到最大列数，避免列错位。

## 三、Word / PDF

- Word 走 `word/document.xml`：表格行拼成一行、标题转成 `环节：` 前缀、列表项转成 `- `。
- PDF 只有 **CID 内嵌字体**（中文很常见）时无法可靠还原文本。
  **不要伪造内容**：解析器必须明确失败并提示"改用 Word/Excel 或自然语言建模"。

## 四、交付形态（离线是硬约束）

| 禁止 | 原因 |
| --- | --- |
| 任何 CDN 外链（含 Tailwind CDN） | 客户现场可能断网，外链挂了页面就白屏 |
| `fetch('samples/*.json')` | `file://` 下被 CORS 拦死，样例永远加载不出来 |
| ES Module `import` | `file://` 下模块脚本同样被拦 |
| 依赖 Python/Node 起本地服务 | 销售机器上没有这些运行时 |

样例必须内联为 `window.SOP_SAMPLES = {...}` 的**经典 script**，
所有第三方库下载到 `vendor/` 后一并内联。打包后用浏览器以 `file://` 打开验证——
那才是客户真实的打开方式。

## 五、其他

- **BPMN 异常分支**：多情况 → parallelGateway 分支；异常 → exclusiveGateway 分支（正常 / 异常两条任务）后汇合。
  用"改接上一段连线"的写法极易把 `incoming/outgoing` 改断，直接新建网关最稳。
- **SVG 多行文本**：不要用 `map().join()` 拼 `<text>`，逐行 `forEach` 输出并递增 `y`。
- **脱敏映射顺序敏感**：长词必须排在短词前面（`客户A国际海运` 要在 `客户A` 之前），否则会替换成半截词。
